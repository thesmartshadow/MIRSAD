# MIRSAD v1.2 Final UI Rebuild

## Executive assessment

MIRSAD now presents itself as a public-content retrieval instrument rather than an administration dashboard. The rebuild replaces the conventional sidebar, nested cards, KPI grid, source table, result cards, and numbered cluster grid with a unified command layer, retrieval field, evidence ledger, capability braid, deterministic cluster constellation, continuous analytics plane, temporal history ledger, and route-specific analytical surfaces.

The work is presentation-only. No API behavior, database semantics, routing, connector, ranking, semantic-scoring, clustering, or coverage semantics were changed. The existing v1.2 retrieval implementation remains authoritative.

## Design direction

The visual grammar is based on **signal, route, acquisition, evidence, time, and coverage**. Open planes, fine registration grids, coordinate marks, source paths, typographic scale, and deliberate contrast replace repeated rounded containers. The palette is mineral paper/graphite with vermilion as the execution signal and teal as the evidence/provenance signal. It deliberately avoids gradients, glassmorphism, neon, random particles, decorative networks, and AI metaphors.

The concise pre-implementation direction is recorded in `reports/v1.2-final-ui-direction.md`. The complete approved-source research matrix is in `reports/v1.2-ui-source-research.md`. Visual research used only the 14 whitelisted sources.

## Runtime selection

- React, shadcn/ui, Tailwind, Lucide, TanStack, and Recharts remain the accessible structural stack.
- GSAP remains the sole motion owner. Route and workspace timelines are scoped with cleanup and disabled under reduced motion.
- SVG is the primary relationship renderer because it is inspectable, accessible, themeable, and driven directly by typed search state.
- Existing Three.js remains the only WebGL renderer. It is lazy, optional, visibility-aware, context-loss-safe, and disposable.
- Pts.js, CSS-Doodle, GL Transitions, Atropos, mo.js, Matter.js, Lenis, OGL, PicoGL, Shader Park, Cables, and the fluid simulator were studied but not added as runtime dependencies.

## Application shell

The generic left navigation was removed. A compact indexed command layer now supplies global identity, current-route context, route switching, locale/theme controls, local status, and a collapsible desktop route aperture. Medium/mobile navigation uses the existing accessible Sheet primitive and opens from the correct logical side in LTR/RTL.

Page identity is continuous across routes through a coordinate axis, route number, dominant heading, and signal rule. Transitions use a short opacity/translation/clip sequence; route changes remain immediate and reduced-motion users receive static state changes.

## Search

### Idle

The query command is visually dominant inside a quiet registration field. The idle SVG shows only the true structural lanes (live, local, historical, MAFER, evidence); it does not simulate source execution. Advanced controls remain progressively disclosed.

### Active

The verified three-panel analyst state remains while searching. Filters, authoritative live progress, and results workspace occupy stable regions. Actual SSE events control selected/active/completed/degraded source state. Local memory is a separate acquisition lane and cannot imply live connector execution.

### Completed

Terminal searches settle into a wide results-first workspace. Filters and Trace remain available as compact controls/Sheets. Results use an editorial evidence ledger rather than repeated cards. Platform and acquisition path remain compact, separate metadata.

### Score explanation

Explain Score retains backend-authoritative values. The visual hierarchy shows final relevance, the 25% lexical / 75% semantic core, the aggregate secondary adjustment bounded to at most 1%, and penalties. Lexical-only state does not fabricate a semantic percentage. The copy explicitly states that relevance is not probability or factual correctness.

## Sources

The large connector table is no longer the primary experience. A capability braid maps acquisition modes into MAFER and then into real platform/category lanes. Each platform node independently encodes health/configuration state and opens a technical inspector. A compact configuration rail keeps safe requirements visible, while the full settings/telemetry table remains a secondary disclosure.

The topology uses only API-provided source state. No source, capability, or relationship is invented. Disabled SearXNG web discovery remains distinct from direct connector failure.

## Clusters

The numbered-circle grid was replaced by a deterministic evidence constellation:

- x position: chronological order from actual first-seen/publication evidence;
- y position: normalized aggregate relevance within dominant-platform lanes;
- node scale: real member count;
- orbit ticks: platform diversity;
- score arc: aggregate relevance within the visible set;
- continuous spine: chronology;
- secondary link: rendered only when real cluster-term Jaccard overlap reaches the fixed threshold.

There is no random seed, force simulation, or fictional connection. The dense accessible evidence ledger remains available below the visualization, and keyboard selection opens actual cluster members.

## Other routes

- **Analytics:** one continuous analytical canvas with aligned signal, timeline, language, platform, and score distributions; all values remain real read-model data.
- **Compare:** a shared comparison plane and baseline replace side-by-side generic cards.
- **History:** a temporal session ledger makes query, execution, status, counts, and duration scan as one chronological record.
- **Saved Searches / Bookmarks:** dense evidence collections support fast scanning and existing actions without floating cards.
- **System:** an engineering console uses precise status typography and structured runtime planes.
- **Settings:** intentionally calm, form-first planes; no experimental visualization was forced into configuration tasks.

## Motion and rendering lifecycle

Motion represents application state: route changed, search started, source state changed, ranking started, evidence became authoritative, inspector opened. Idle and terminal views settle; no decorative loop remains active.

The existing Three.js topology is dynamically loaded behind the search route. It uses a bounded renderer, capped pixel ratio, resize handling, visibility pause, terminal on-demand rendering, context-loss fallback, and disposal of renderer/geometry/material/listeners. Search and readable text remain DOM/SVG based. Playwright verified reduced motion and a forced WebGL-off path.

## Accessibility, RTL, and responsive behavior

- Axe found no serious/critical issues on key analytical routes in English and Arabic.
- Interactive SVGs use grouped semantics with titled/described surfaces and individually labeled keyboard nodes; they are not misrepresented as a single nested interactive image.
- Mobile navigation, Sheets, Dialogs, Selects, Dropdowns, and Tooltips retain focus management and logical RTL sides.
- Twenty consecutive locale switches preserved the query and collapsed navigation state.
- Arabic desktop, Arabic active/results, 390 px mobile, reduced motion, and WebGL fallback were captured from the running application.
- Identifiers, URLs, source names, scores, and mixed-language query text retain direction isolation.

## Security

- No AI-generated or external visual assets were added.
- Retrieved content continues to render through React text nodes; no retrieved HTML injection path was added.
- The only `dangerouslySetInnerHTML` occurrence is the existing shadcn Chart theme-style generator, not external content.
- No frontend API key, token, secret, private key, arbitrary remote fetch, connector host, or new network transport was introduced.
- Browser evidence recorded no console error, React warning, unhandled promise rejection, WebGL error, or GSAP cleanup warning.

## Known limitations

- Bluesky returned an external HTTP 403 during the final low-cost source probe. The UI correctly presents current external availability separately from configuration; this is not a visual or application failure.
- Three.js remains a large lazy chunk. It is optional and does not delay the query instrument; replacing the renderer was explicitly rejected because it would add migration risk without improving retrieval understanding.
- A cluster field with genuinely homogeneous records will correctly show limited platform/similarity variation. The visualization does not add noise or fictional structure to make sparse data look richer.

## Final assessment

The rebuilt UI is a coherent, localized retrieval instrument. It is no longer the previous dashboard with added effects: route composition, search-state geometry, result structure, source inspection, cluster encoding, analytics layout, and secondary route hierarchies have all changed while verified retrieval behavior remains untouched.
