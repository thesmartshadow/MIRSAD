# MIRSAD v1.2 Final UI Direction

## Design Thesis

MIRSAD is a retrieval field, not a dashboard. Its visual hierarchy follows the evidence path: route context, query, acquisition state, authoritative evidence, and secondary analysis. The interface uses open planes, typographic anchors, coordinate marks, and data-bound paths instead of stacked cards and generic KPI grids.

## Visual Grammar

- **Navigation aperture:** a compact indexed route rail expands contextually without becoming a conventional sidebar. Active-route geometry remains visible while labels stay immediately accessible.
- **Retrieval field:** Search changes composition across idle, active, and terminal states. Real SSE state controls the acquisition topology; terminal state settles into a wide evidence ledger.
- **Evidence ledger:** results use an editorial record structure with a source index, reading column, provenance line, compact score instrument, and actions. Repeated floating cards are removed.
- **Analytical continuum:** Analytics uses one shared visual plane with a dominant temporal signal and aligned distributions rather than independent chart cards.
- **Evidence space:** Clusters use deterministic coordinates derived from time, platform diversity, member count, and aggregate relevance. No random or force-based placement is used.
- **Capability braid:** Sources maps acquisition modes through MAFER to real platforms and health states. The technical table remains an accessible secondary inspector.
- **Temporal and comparative planes:** History is a chronological session ledger; Compare uses a shared baseline; Saved Searches and Bookmarks are dense working collections; System is an engineering trace; Settings remains calm and form-first.

## Approved-Source Traceability

| System | Approved source | Technique transformed for MIRSAD | Runtime |
|---|---|---|---|
| Route and workspace transitions | Codrops Creative Hub, Grid Flow, navigation experiments | Spatial continuity, anchored transformations, masked context reveal | GSAP + CSS |
| Retrieval topology | Codrops SVG/path experiments, Pts.js | Typed vector paths and deterministic point relationships driven by SSE state | SVG + GSAP |
| Procedural field | CSS-Doodle | Seeded registration grid and low-contrast directional field, recreated with native CSS | CSS |
| Search depth | OGL and PicoGL studies, existing Three.js architecture | One bounded GPU scene with explicit lifecycle; no second renderer | lazy Three.js |
| Pipeline composition | Cables.gl | Data-flow hierarchy and connections translated into real acquisition lanes | SVG/DOM |
| Major state changes | GL Transitions and Codrops grid transitions | Structural continuity without a shader crossfade or cinematic delay | GSAP |
| Inspector depth | Atropos | Restrained layered depth for selected analytical context, without card tilting | CSS transforms |
| Micro feedback | mo.js | Small state-confirmation choreography owned by the existing GSAP system | GSAP |
| Cluster geometry | Pts.js, Matter.js study | Data-derived spatial packing; physics rejected to preserve deterministic positions | SVG |
| Acquisition flow | WebGL Fluid Simulation study | Direction, velocity, and dissipation principles reduced to bounded path flow; fluid runtime rejected | SVG + GSAP |
| Procedural state form | Shader Park | Scalar state encoded through geometry, not an abstract decorative blob | SVG/Three.js |
| Scrolling | Lenis | Native scrolling retained after evaluating application, keyboard, dialog, and RTL requirements | Browser native |

## Technology Selection

- React, shadcn/ui, Tailwind, and Lucide remain the structural and accessible UI stack.
- GSAP remains the single motion owner. Timelines are scoped and reverted on unmount.
- SVG is the primary data-relationship renderer.
- Existing Three.js remains the only WebGL renderer and is lazy, optional, pausable, and disposable.
- Pts.js, CSS-Doodle, GL Transitions, Atropos, mo.js, Matter.js, Lenis, OGL, and PicoGL.js are not added as runtime dependencies because their useful principles can be implemented with the existing stack without competing loops or bundle cost.

## Acceptance Constraints

- No fictional nodes, traffic, health, evidence, or charts.
- Motion stops when state settles and respects reduced motion.
- Text and controls remain DOM-based, selectable, localized, keyboard accessible, and bidi-safe.
- WebGL is never required for search or navigation.
- Search input and route shell are interactive before creative chunks load.
