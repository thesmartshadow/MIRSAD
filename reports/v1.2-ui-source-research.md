# MIRSAD v1.2 Whitelist UI Research Matrix

Recorded before frontend implementation. Visual and interaction research was restricted to the 14 user-approved sources. No image-generation tool, template gallery, UI gallery, or non-whitelisted design reference was used.

| Source | Technique studied | What was learned | Potential MIRSAD application | Decision | Why | Runtime dependency |
| --- | --- | --- | --- | --- | --- | --- |
| [Codrops Creative Hub](https://tympanus.net/codrops/hub) | Grid continuity, typographic composition, SVG paths, masks, GSAP timelines | A state change reads clearly when spatial relationships persist and only the changed layer moves | Query-to-acquisition-to-evidence workspace transitions and route identity | Accept principles | Directly communicates search state without decorative motion | Existing GSAP + CSS + SVG |
| [Pts.js](https://ptsjs.org/) | Responsive point/vector spaces and player lifecycle | A small number of real points and edges can encode relationships without a force-graph spectacle | Coverage and cluster geometry generated from actual records | Accept principles | Data topology is useful, but another canvas runtime is unnecessary | None; implement with SVG/Canvas already present |
| [CSS-Doodle](https://css-doodle.com/) | Seeded procedural grids and mathematical repetition | Registration patterns can establish an instrument-like field at very low contrast | Deterministic coordinate/grid motif in shell and idle search | Accept principles | CSS can provide the motif without a custom element/runtime | None; authored CSS |
| [GL Transitions](https://gl-transitions.com/) | GPU interpolation between visual states | Shader transitions are appropriate only for rare, large state changes | Idle-to-active or active-to-results transition | Reject runtime | Existing GSAP spatial continuity is clearer, cheaper, and more accessible | None |
| [Atropos](https://atroposjs.com/) | Bounded layered pointer depth and explicit destroy lifecycle | Depth can identify an inspected object, but repeated tilt harms scanning | Optional selected evidence focus | Reject runtime | MIRSAD result ledgers need stable geometry and text selection | None |
| [mo.js](https://mojs.github.io/) | Timeline-coordinated shapes and bounded bursts | Microfeedback should be brief and tied to a completed action | Bookmark/source-complete confirmation | Reject runtime | Existing GSAP can express the same states without a second motion owner | None |
| [Matter.js](https://brm.io/matter-js/docs/) | Rigid-body engine, runner, composites and collision | Physics is useful only when collision/packing is itself analytical | Cluster packing experiment | Reject | It would create moving, completion-order-sensitive spatial output with no retrieval benefit | None |
| [WebGL Fluid Simulation](https://paveldogreat.github.io/WebGL-Fluid-Simulation/) | Velocity, dissipation, feedback and pointer-driven fields | Flow persistence can suggest acquisition movement, but fluid imagery easily becomes decorative | Active retrieval flow | Reject runtime | Real source paths are discrete and better represented by typed SVG lines | None |
| [Cables.gl](https://cables.gl/docs/) | Node-based shader composition and explicit pipeline stages | Complex rendering stays maintainable when stages and ownership are explicit | Internal model for the topology render pipeline | Accept architecture principle | Production must stay local and cannot depend on the editor/cloud | None |
| [PicoGL.js](https://tsherif.github.io/picogl.js/) | Explicit WebGL2 buffers, programs and draw calls | Low-level renderers reduce abstraction but increase lifecycle/security burden | Small topology renderer | Reject | Existing lazy Three.js already satisfies the bounded renderer requirement | None |
| [Lenis](https://lenis.dev/) | Smooth-scroll lifecycle and nested-scroll considerations | Application panes, tables, Sheets and keyboard navigation are harmed by global scroll mediation | Global navigation/route scroll | Reject | Native scrolling is immediate, accessible and correct for an analyst workspace | None |
| [Codrops Playground](https://tympanus.net/codrops/category/playground/) | SVG line systems, clip/mask transitions, grid changes, menu choreography and canvas experiments | Several small techniques synthesize better than copying a single demo | Shell navigation indicator, results expansion, coverage reveal | Accept principles | Supports an original state-driven composition | Existing GSAP + CSS + SVG |
| [Shader Park](https://shaderpark.com/) | Procedural geometry and signed-distance-form thinking | A procedural object is meaningful only if geometry maps to data dimensions | Coverage-state object | Reject runtime | Coverage is categorical and would be obscured by an abstract form | None |
| [OGL](https://github.com/oframe/ogl) | Minimal renderer/geometry/program lifecycle | A smaller renderer is attractive only if replacing, rather than duplicating, the current stack | Retrieval topology | Reject | Migrating the verified Three.js topology adds risk without analytical value | None |

## Runtime selection

- Structure and accessibility: React, shadcn/ui primitives, Tailwind and application tokens.
- Motion ownership: the existing GSAP motion module only.
- Vector/data graphics: authored SVG driven by typed runtime data.
- GPU rendering: the existing single lazy Three.js topology renderer, with SVG fallback.
- Procedural identity: deterministic CSS registration grids and coordinate marks; no new dependency.
- Rejected runtime additions: Pts.js, CSS-Doodle, GL Transitions, Atropos, mo.js, Matter.js, fluid simulation, Cables, PicoGL, Lenis, Shader Park and OGL.

## Source-to-component traceability

| Component | Source inspiration | Technique | Product reason | Runtime |

| Retrieval/Coverage topology | Pts vector-space principles + Codrops SVG paths | Actual source/lane nodes connected to evidence stages | Shows executed, local, historical and missing acquisition truthfully | SVG + existing Three.js fallback pair |

| Cluster field | Pts geometry principles | Deterministic positions derived from real cluster order/size | Adds relational overview while preserving a list alternative | SVG |
| Route transitions | Codrops grid continuity | Short opacity/transform continuity | Preserves context without cinematic delay | GSAP |
