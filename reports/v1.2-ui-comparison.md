# MIRSAD v1.2 UI Comparison

This comparison is grounded in the v1.1.1 screenshots, the pre-implementation route audit, the v1.2 running application, and the final Playwright screenshot matrix. Visual research was restricted to the 14 sources recorded in `v1.2-ui-source-research.md`; no generated assets, template gallery, or outside UI reference was used.

## Application shell

**Before.** Navigation read as a conventional component-library sidebar. Page title, subtitle, and similarly weighted bordered containers repeated across routes, weakening global orientation.

**After.** A numbered retrieval rail, persistent route marker, compact context bar, registration-grid field, and shared instrument header create one application-specific hierarchy. GSAP performs only short route/state continuity transitions and reverts scoped timelines on unmount. This reduces identical chrome, preserves one-interaction navigation, and keeps native scrolling.

**Source-derived concept.** Codrops grid continuity and navigation choreography, synthesized with CSS-Doodle's deterministic-grid principle using authored CSS rather than another runtime.

## Search

**Before.** v1.1.1 already had truthful streaming and results-first completion, but coverage lived in diagnostics and the idle, active, and evidence states were visually related only through the central workspace.

**After.** The query instrument remains dominant while typed execution state drives the existing SVG/Three.js topology. The completed state settles into a wide evidence ledger. Coverage is a first-class contextual tab with LIVE, LOCAL MEMORY, HISTORICAL, and GAPS planes; an unexecuted Bluesky connector can coexist visibly with Bluesky evidence acquired from local memory.

**Measured improvement.** One click reaches Coverage from a stored session. Platform, acquisition lane, requests, contribution, current health, and planner reasons are visible without inspecting logs. No fictional node or source activity is rendered.

**Source-derived concept.** Codrops state continuity plus Pts.js point/vector relationship principles, implemented with typed DOM/SVG data and the existing lazy Three.js renderer.

## Results and provenance

**Before.** Evidence records were correct but repeated bordered surfaces and categorical badges consumed horizontal and visual bandwidth.

**After.** Results read as ruled evidence rows. Typography establishes platform/author/time, title, snippet, provenance, relevance, and actions in that order. `Platform` and `Acquired through` remain compact independent facts. Explain Score continues to show the authoritative 25% lexical / 75% semantic core, the combined secondary adjustment as a bounded <=1% layer, and penalties separately.

**Measured improvement.** Terminal desktop rails collapse automatically, making the center reading plane materially wider; result access remains immediate and filters/trace reopen through keyboard-accessible controls.

**Source-derived concept.** Codrops editorial grids and bounded state transitions; no Atropos tilt or shader transition was adopted because stable text geometry is more useful.

## Analytics

**Before.** Generic KPI cards gave every total equal container weight before the actual analytical charts.

**After.** Large persisted figures share a numerical signal band and thin baselines; scope, content/session semantics, and chart planes retain their backend-authoritative behavior. The page reads as an analytical surface rather than a dashboard card grid.

**Source-derived concept.** Codrops asymmetric typography and grid composition.

## Clusters

**Before.** The accessible list was authoritative but relative cluster size and relationships were difficult to scan.

**After.** A deterministic SVG field uses real cluster order and member counts, paired with the existing accessible ledger. Empty state renders no invented geometry.

**Source-derived concept.** Pts.js responsive geometry principles without adding a canvas runtime or a completion-order-sensitive force simulation.

## Compare

**Before.** Two conventional boxed columns emphasized containers rather than shared metrics and differences.

**After.** The route uses the common instrument plane, closer parallel baselines, and reduced Card chrome while retaining the persisted comparison read model and controls.

**Source-derived concept.** Codrops grid continuity. A shader transition was rejected because it would delay numerical comparison.

## History

**Before.** The authoritative table appeared primarily as CRUD history.

**After.** A temporal spine, execution marks, tighter query typography, and aligned persisted metrics turn sessions into a chronological retrieval ledger. Exact session navigation and refresh behavior are unchanged.

**Source-derived concept.** Codrops line systems and typographic rhythm.

## Saved searches and bookmarks

**Before.** Repeated item containers separated related working-set metadata and actions.

**After.** Both routes use the shared evidence-ledger language and reduced surface chrome. Saved configuration, canonical content identity, notes, and persistence controls remain authoritative.

**Source-derived concept.** Codrops editorial grids. Atropos and mo.js runtimes were rejected because neither improves scanning or accessibility.

## Sources

**Before.** Correct source cards still made capability, configuration, acquisition, and current health look like one visual dimension.

**After.** A real-data SVG topology and capability ledger distinguish platform, acquisition support, configuration, and current health. Web discovery disabled remains distinct from direct connector failure.

**Source-derived concept.** Pts.js vector relationships and Codrops SVG line systems, implemented as accessible inline SVG.

## System

**Before.** Green/red status cards resembled generic dashboard health tiles.

**After.** A console-like signal band and ruled runtime sections show API, database, FTS, semantic capability, connector distribution, storage, and version with more compact scan paths.

**Source-derived concept.** Codrops line systems; no decorative simulation.

## Settings and report views

**Before.** Settings were usable but inherited the same Card-first formula; report detail felt detached from the shell.

**After.** Settings remain intentionally calm, with shared hierarchy and less chrome. Report/detail views use the same route instrument and evidence sections. No experimental renderer runs in forms.

## Responsive, motion, and rendering

- Arabic direction remains root-owned; technical identifiers and URLs retain bidi isolation.
- Mobile is single-column with no horizontal overflow; contextual controls remain Sheets where appropriate.
- Reduced-motion mode preserves states while disabling nonessential movement.
- WebGL remains optional, lazy, data-driven, and disposable. `?webgl=off` produces the SVG fallback and zero canvases.
- The production build keeps Three.js in a separate 724.23 kB / 184.67 kB gzip lazy chunk; the main chunk is 305.91 kB / 96.37 kB gzip.
- Bounded browser stress moved from 28,380,848 to 25,597,952 JS heap bytes and from 4,551 to 2,681 DOM nodes; no monotonic resource growth was observed.
- Native scrolling is retained. Lenis, physics, extra animation engines, low-level WebGL stacks, fluid simulation, and shader transitions were rejected.

## Evidence
