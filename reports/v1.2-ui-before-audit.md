# MIRSAD v1.2 UI Before Audit

This audit uses the v1.1.1 running application, screenshots, route source, and existing tests. It was recorded before v1.2 frontend edits.

## Cross-application findings

- The search route has a strong precision-instrument direction, but the rest of the application still follows a repeated title/subtitle/Card-grid composition.
- Repeated borders, rounded containers, badges and identical padding obscure which information is primary, contextual, or actionable.
- Navigation remains recognizably a component-library sidebar rather than an application-specific retrieval map.
- Analytics and System lead with generic KPI/status cards; dense evidence routes underuse horizontal rules, shared baselines and typographic scale.
- Search provenance is clear, but coverage, historical lanes and reasons for source participation are not first-class views.
- Existing GSAP/SVG/Three.js behavior is localized to Search. Route continuity and visual ownership across the shell are weak.
- Existing RTL/root direction and mobile Sheets are sound and must remain. Technical strings already use direction isolation in key search surfaces.

## Acceptance measurements

- Reduce nested Card composition and the number of same-weight bordered surfaces.
- Increase completed-result usable width without increasing line length beyond readable bounds.
- Keep route navigation at one interaction and preserve keyboard focus.
- Add no fake nodes, charts, traffic, or placeholder evidence.
- Keep one WebGL renderer maximum, lazy and disposable; use SVG/static fallbacks elsewhere.
- Keep native scrolling, reduced-motion behavior, mobile no-overflow, and root-level RTL.
